# Networking & models (Dio + Freezed/json_serializable)

## Dio — one client, interceptors do the cross-cutting work

A single `Dio` instance per base URL (auth API, Gmail API, …), built once in `core/network/` and
injected via a Riverpod provider — never instantiate `Dio()` ad hoc inside a repository method.

```dart
@riverpod
Dio mailApiDio(Ref ref) {
  final dio = Dio(BaseOptions(baseUrl: Env.mailApiBaseUrl));
  dio.interceptors.addAll([
    AuthInterceptor(ref), // attaches/refreshes the bearer token
    RetryInterceptor(dio: dio, retries: 2),
    if (kDebugMode) LogInterceptor(responseBody: false),
  ]);
  return dio;
}
```

**Token refresh belongs in an interceptor, not scattered try/catch blocks per call site.** A 401
response triggers one refresh attempt and replays the original request; if refresh itself fails, the
interceptor signs the user out — this mirrors the Next.js BFF rule that "session lifecycle is part of
the deliverable", not an afterthought wired in later.

```dart
class AuthInterceptor extends Interceptor {
  AuthInterceptor(this.ref);
  final Ref ref;

  @override
  void onError(DioException err, ErrorInterceptorHandler handler) async {
    if (err.response?.statusCode == 401) {
      final refreshed = await ref.read(authRepositoryProvider).refreshToken();
      if (refreshed) {
        final retried = await ref.read(mailApiDioProvider).fetch(err.requestOptions);
        return handler.resolve(retried);
      }
      await ref.read(authRepositoryProvider).signOut();
    }
    handler.next(err);
  }
}
```

**Distinct upstream failures map to distinct app-level results** — a repository method returns a typed
result (`MailFailure.unauthorized`, `.notFound`, `.network`, `.unknown`), never a bare rethrow of
`DioException` into the UI layer. The UI renders different states for each, the same rule as the
Next.js BFF not collapsing 401/403/404/502 into one generic error.

## Models — Freezed is the source of truth, never a hand-cast response

**Responses are parsed, not cast.** `Mail.fromJson(response.data)` (generated by `json_serializable`)
is the only way a network response becomes app data — never `response.data['subject'] as String`
scattered through a repository. A backend rename then fails loudly at `fromJson` instead of silently
rendering `null`.

```dart
@freezed
class Mail with _$Mail {
  const factory Mail({
    required String id,
    required String subject,
    required String sender,
    required DateTime receivedAt,
    @Default(false) bool isRead,
  }) = _Mail;

  factory Mail.fromJson(Map<String, dynamic> json) => _$MailFromJson(json);
}
```

**Types mirror the backend response field-for-field (MUST).** No app-side DTO that renames or
re-derives a field under a different name — exactly the rule the Next.js house rules state for API
clients, and the same failure mode: a `subject` field quietly computed from `title ?? 'No subject'`
displays the wrong thing the moment the backend's actual field is `subject`, not `title`. Derive display
values **at the widget**, not inside the model.

**Unions model state exhaustively, not a nullable-field soup.** A mail-sync result, a form-submission
outcome, or a repository failure is a sealed Freezed union consumed with `.when`/`.map` — never a class
with three nullable fields where "which one is set" encodes the actual state:

```dart
@freezed
sealed class SyncResult with _$SyncResult {
  const factory SyncResult.success(List<Mail> mails) = SyncSuccess;
  const factory SyncResult.unauthorized() = SyncUnauthorized;
  const factory SyncResult.networkError(String message) = SyncNetworkError;
}

// consumed exhaustively — the compiler enforces every case is handled
result.when(
  success: (mails) => _showMails(mails),
  unauthorized: () => _promptSignIn(),
  networkError: (message) => _showError(message),
);
```

## Mocks are typed to the real contract

When a backend endpoint doesn't exist yet, build the repository against a mock data source that
returns the **same Freezed model**, pinned with the model's own constructor (not a raw `Map` literal
shaped by guesswork) — so swapping the mock for the live endpoint later is a one-line provider override,
not a UI rewrite. Mark any field whose shape is genuinely unconfirmed with a `// PROPOSED` comment next
to it, same convention as the Next.js rules' handoff-doc practice.
